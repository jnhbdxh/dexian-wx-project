## 1. 真实请假保存即生效

### 1.1 不按登记时间区分

排班人员登记的是已经确定的真实请假。无论请假从当前时刻开始，还是提前登记明天、下周或未来未排班日期，保存后都立即成为有效的 `leave` 事实，并参与可用性判断。

请假的处理方式不取决于：

- 是否突然发生；
- 请假开始时间距离现在多久；
- 目标日期是否已经发布排班；
- 当时是否已有预约冲突。

系统一期不增加员工请假申请、草稿或审批流程。排班人员点击保存前，界面明确提示“保存后立即生效；受影响的待确认申请将失效，已确认接待需要人工处理”。

### 1.2 与普通计划调整的边界

| 操作                             | 类型             | 保存或发布规则                 |
| -------------------------------- | ---------------- | ------------------------------ |
| 登记今天或未来的真实请假         | `effective_fact` | 保存即生效，冲突不能阻止保存   |
| 移动餐休                         | `planned_change` | 先检查冲突，未解决时禁止发布   |
| 新增或移动培训                   | `planned_change` | 先检查冲突，未解决时禁止发布   |
| 普通调整上下班时间或班次         | `planned_change` | 先检查冲突，未解决时禁止发布   |
| 设备突然故障等必须如实登记的事件 | `effective_fact` | 保存即生效，之后处理受影响接待 |

V5 中“预先申请休假属于 `planned_change`”以及“按提前计划或突发事实区分请假”的表述作废。系统没有“预先申请休假”这一业务状态；只要排班人员保存请假，就是有效事实。

## 2. 请假保存事务

请假开始和结束时间允许位于未来，也允许覆盖尚未发布排班的日期。保存事务执行：

1. 校验操作者具有排班及请假登记权限，并校验人员、门店、起止时间和原因；
2. 按 V4 已确定的统一锁序，取得请假区间及所有受影响接待组完整日期集合的锁；
3. 插入有效 `leave` restriction 和审计事件；
4. 找出与准备、服务或整理片段不兼容的全部接待；
5. 对 `held` 待确认接待整组标记失效，原子释放该组全部美容师、房间和床位占用；
6. 对 `confirmed` 接待保留原承诺和原分配，为每个受影响接待创建去重的冲突待办；
7. 提交后，所有可约查询立即排除该请假区间；
8. 返回请假已生效、失效待确认数量、受影响已确认数量及相应处理入口。

冲突不会导致请假事务回滚。即使存在其他空闲美容师，也不自动改派：待确认申请已经失效；已确认接待必须由前台联系顾客后明确改期或换人。

若请假只覆盖美容师所需的连续休息，没有覆盖准备、服务或整理，则接待保持有效，请假时间可以按 V5 规则满足休息，不生成冲突待办。

## 3. 未来未排班日期

请假不依赖班次记录存在。未来日期尚未生成或发布排班时，仍可先保存请假。后续生成、调整或发布排班必须读取已生效请假：

- 基础班次允许与有效请假相交并保持完整记录；计算有效工作区间和可约时间时，必须从基础班次中扣除请假区间；
- 已保存请假不会因后来生成或发布基础班次而被覆盖、撤销，也不会使请假区间重新可约；
- 培训、会议、值班等具体工作安排不得落入请假区间；存在相交时，这些工作安排发布失败并指明现有请假；
- 取消或更正请假必须作为有权限、有原因、有审计记录的独立操作，不能通过改班隐式删除。

## 4. 新增待执行验收用例

以下仍是核心业务实现后的待执行用例，不表示当前已经通过自动化测试。

### 提前登记明日请假，同时撞预占和确认接待

前置条件：

- 今天为 D，排班人员登记美容师 A 在 D+1 13:00—18:00 请假；
- D+1 14:00 有一组使用美容师 A 的 `held` 待确认接待；
- D+1 16:00 有一组使用美容师 A 的 `confirmed` 已确认接待；
- 美容师 B 在上述时间均空闲。

预期结果：

1. 请假保存成功并立即生效，不因两个冲突而拒绝；
2. 14:00 待确认接待整组失效，美容师、房间和床位全部释放；
3. 系统不把 14:00 待确认接待自动转给美容师 B；
4. 16:00 已确认接待和原分配保留，生成一个可追踪、可去重的冲突待办；
5. 系统不把 16:00 已确认接待自动转给美容师 B；
6. 新的可约查询不再返回美容师 A 在请假区间的候选；
7. 返回结果清楚显示“请假已生效、1 组待确认已失效、1 组已确认待处理”。

### 先登记请假，后生成基础班次

前置条件：

- 已登记美容师 A 明天 13:00—14:00 的有效请假；
- 随后生成并发布美容师 A 明天 09:00—18:00 的基础班次。

预期结果：

1. 09:00—18:00 基础班次可以正常保存和发布，不要求前台拆成两段；
2. 有效工作区间为 09:00—13:00 和 14:00—18:00；
3. 13:00—14:00 请假记录继续有效，不被班次覆盖或撤销；
4. 可约查询不得返回落入或穿过 13:00—14:00 请假区间的候选；
5. 培训、会议或值班等具体工作仍不得发布到 13:00—14:00。

- [ ] 今天登记明天或更远日期的真实请假仍保存即生效；
- [ ] 请假不依赖目标日期已有排班；
- [ ] 基础班次允许与请假相交，有效工作区间和可约时间会扣除请假；
- [ ] 后生成或发布的基础班次不会覆盖、撤销请假；
- [ ] 培训等具体工作安排仍不得落入请假区间；
- [ ] 请假冲突不会阻止保存；
- [ ] 受影响 held 整组失效并释放，不自动换人；

- [ ] 移动餐休、培训和普通改班仍在冲突未解决时禁止发布；
- [ ] 没有新增员工请假申请或审批流程；
