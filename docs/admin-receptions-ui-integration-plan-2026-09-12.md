## 1. 本轮目标与现有结论

完成两个独立示例及真实接待页的浏览器 200% 缩放验证；在明确文件分工和业务依赖后，将公共界面接入真实接待查询页面，保留真实字段、权限和恢复机制，完成操作位置恢复及真实链路验收。接待查询通过后，再推广到请假与冲突页面。

公共组件与两个示例的四项交互修复、五项视觉精修及结果区 16px 间距已由用户复核关闭。真实浏览器 200% 缩放仍未验收，暂不恢复完整 ship 结论。历史 108 项后台测试、类型检查和构建结果仅作历史参考，不作为本轮修改后的通过证据。

沿用森林绿、浅色背景、白色工作面板和中文系统字体。普通工作区最大宽度 1240px；主标题桌面 30px、面板标题约 20px、对象 16px、正文及输入 14px；主要控件至少 44px，字段圆角 9px，面板保留舒适留白。不同对象清楚分隔，长信息自然展开，不以首屏条数或固定记录高度优化。具体约定沿用公共组件 README。

## 3. 先完成查询逻辑协作，再接入展示

当前接入依赖已经明确：普通读取失败会清空列表，后台详情刷新失败会清空详情；翻页在成功前改变游标与历史；页面只在详情成功后定位，返回时聚焦列表容器。公共展示组件无法单独解决这些行为。

实现前双方固定以下状态与事件含义，具体 TypeScript 命名由实际代码决定，不引入新通用状态框架：

| 情况                   | 查询逻辑负责                                                             | 页面负责                                                         |
| ---------------------- | ------------------------------------------------------------------------ | ---------------------------------------------------------------- |
| 首次读取／新条件查询   | 新查询清除旧结果、详情和分页可用性；成功后建立新结果归属                 | 清楚显示已应用条件、首次加载或失败；无首页结果不能翻页           |
| 同一查询手动／自动刷新 | 允许查看且身份、对象未变化时保留数据；输出更新中、失败及最后成功数据时间 | 保持内容、选择、输入、滚动和焦点；旧数据明确标注                 |
| 同一详情后台刷新失败   | 保留仍允许展示的当前详情，输出独立刷新错误和数据时间                     | 提示更新失败，不误表示详情不存在                                 |
| 切换详情／详情首次失败 | 清除前一对象详情；隔离过期响应，提供当前请求完成或失效依据               | 成功、失败均可定位当前详情区域；旧请求不得移动焦点               |
| 翻页                   | 以候选游标请求，成功后提交游标及历史；失败保留原页、数据、历史和应用条件 | 页码仅反映已取得结果；错误及重试指向本次读取                     |
| 游标失效               | 沿用必要的首页恢复策略；恢复成功才提交首页状态，失败不可假装已返回首页   | 成功返回首页明确提示；恢复失败标明当前数据已旧，提供重新查询入口 |
| 身份变化／查看权限失效 | 按现有保护要求立即清除受保护列表、详情和分页，忽略旧身份响应             | 不显示残留对象，不把焦点恢复到已清除记录                         |
| 确认成功、后续读取失败 | 独立保存确认事实与读取错误；重试仅读取                                   | 同时展示确认成功和刷新未取得，不诱导重新确认                     |
| 确认结果未知           | 保留原请求及现有核实与离开保护；不得生成新请求绕过保护                   | 核实入口与原操作摘要持续可见；查询、重置等锁定                   |

区分首次／新查询忙碌、翻页忙碌和后台刷新。不能直接将后台刷新状态传入 AdminFilters 的 busy，导致整个字段集禁用、正在编辑的控件失焦。公共组件负责其自有按钮防重，页面和查询逻辑继续负责业务请求防重。

实际定时逻辑包含每 15 秒自动刷新，以及待确认期限到达后的轮询刷新触发；两者均纳入回归。不得以统一外观为由取消期限校正、改变确认幂等或请求核实协议。

## 4. 接待页面接入与筛选约定

按页面框架、筛选区、反馈、分页依次接入，复制组件仅用于允许复制的内容。保留现有导航、真实字段、资源占用及支付信息。详情中服务时间、准备整理、必要休息、床房、金额与支付状态继续清楚区分；时间经过不表示实际完工。

筛选保留服务日期、状态、美容师、完整接待号及既有编号校验。重置日期为北京时间当天，清空其他三项；仅修改输入，不发送请求。日期不能依据浏览器本地时区直接推断。

输入条件与已应用条件分别维护；不同则提示“筛选条件已修改，查询后生效”等明确文案。列表和页码归属于已应用条件。自动刷新仍读取已应用条件，不覆盖编辑中的输入。提交新查询后清除旧结果与详情，失败不得将旧结果呈现为新条件结果。默认重置后由操作人员再次查询。

查询仅走表单提交路径，点击与 Enter 不重复触发；重置只处理重置事件。未知操作锁定期间查询和重置均不可用，插槽控件和业务方法也须保留保护。

## 5. 位置恢复与连续操作验收

| 路径               | 必须满足的结果                                                                                 |
| ------------------ | ---------------------------------------------------------------------------------------------- |
| 查看详情成功／失败 | 窄屏焦点与视区进入当前详情标题或错误反馈；保留返回入口，失败不残留上一对象详情                 |
| 返回列表           | 保存记录标识、原索引及滚动位置；优先原记录，移除后定位相邻记录，列表为空定位结果标题；保留筛选 |
| 快速切换记录       | 较早响应不得覆盖当前对象或把焦点拉回；失败也受相同请求次序保护                                 |
| 自动刷新           | 不调用主动定位，不自动滚动，不打断筛选编辑；允许展示的内容保持稳定                             |
| 刷新失败再恢复     | 失败标注旧数据与时间；恢复成功清除失效提示，不重置编辑条件或位置                               |
| 确认后移出列表     | 保留确认结果；返回采用相邻记录或空结果标题，不定位不存在的行                                   |
| 身份／权限变化     | 立即清除不再允许查看的内容；正在进行的旧请求不能恢复旧身份数据                                 |
| 未知结果后核实     | 持续保留原操作和核实入口，不能以重置、重复提交或离开绕过；核实结果与后续读取分别反馈           |

焦点和位置由真实页面决定，通用反馈组件不猜测。定位结果时不隐藏风险或截断长文本。继续保留可见键盘焦点和复制失败后的手动选择能力。

## 8. 实施顺序与交付门槛

1. 先完成共同基线收口，登记共同提交、继承迁移链、整合负责人及统一回归；再确认文件负责人和共同修改窗口，采集局部快照；同时核对真实缩放与联调环境。
2. 双方固定状态输出和责任，实现刷新保留、分页提交与条件归属等已识别依赖，补逻辑回归。
3. 接入接待页公共界面，补重置、位置恢复和页面交互测试；样式限定在已约定范围。
4. 完成普通尺寸与真实 200% 浏览器验证，执行修改后工程检查和产物检查。
5. 完成真实后端及小程序完整链路验证，汇总差异与证据，再决定是否进入请假与冲突页面。

交付包括：责任清单、基线与最终文件哈希／差异、公共接口使用说明更新、截图、连续操作记录、分层测试结果、失败项和未执行项。每条证据注明验证方式、时间、被测版本、预期与实际结果，涉及真实数据时补测试门店／账号角色和接待号，避免记录凭据。

验收分别记录“界面接入与模拟回归”“真实浏览器与缩放”“真实后端联调”“小程序完整链路”，不能合并成一个模糊的通过状态。任一必需项目未执行时明确保留限制；接待查询通过后才推广其他真实页面，不提前认定完整后台或营业上线通过。
