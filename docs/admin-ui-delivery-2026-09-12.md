## 两个演示

**接待查询与详情**：筛选编辑与已应用条件分开；提交新查询后清除旧列表及详情。支持正常与跨日多人详情、首次/新查询失败、刷新失败保留旧数据、翻页失败保持页码、追加及追加失败、独立详情失败、无权限、只读、身份变化清除内容、确认结果未知核实、确认成功但刷新失败及处理后移出列表。请求序号避免旧详情覆盖新选择；同对象刷新保持内容节点，窄屏查看后可返回原列表行与阅读位置。

**请假登记**：按“填写信息 → 查看影响 → 核对影响与下一步 → 确认登记”推进，确认动作放在影响区，窄屏查看影响后定位其标题。覆盖明确成功、明确失败、保存成功仍有待办，以及结果未知后核实成功。未知期间保留原操作摘要并锁定普通提交、重置和工作区离开；核实后允许绿色成功与橙色待办同时出现。已确认接待仍保留，界面不暗示自动取消、改期或更换人员。

两页均使用固定虚构数据、固定模拟时间与内存延迟。顶部“重置演示并应用”是明确清空模拟操作的评审工具，独立于工作区保护；本演示不实现真实幂等写入、账号校验或跨刷新/重新登录恢复。

## 样式默认与局部例外

- 先加载既有全局主题，再加载 [admin-ui.css](../apps/admin/src/components/admin-ui/admin-ui.css)；示例布局由 [preview.css](../apps/admin/src/dev/admin-ui/preview.css) 补充。公共样式不依赖业务页面祖先类名。
- 页面默认最大宽度 1240px，可由 `--admin-ui-page-width` 局部覆盖；正文 14px、行高 1.6，面板标题 20px，面板圆角 16px、内边距 24px。面板以白底与细边界区分层级，本批未给公共面板额外添加阴影。
- 主按钮、输入与选择区域最小高度 44px，可自然增高；键盘焦点使用清晰外圈。编号和辅助说明可用 12–13px，关键时间、金额、影响和禁用原因保持正文可读尺寸。
- 接待布局在不大于 820px 时转单栏并显示返回列表动作；请假布局在不大于 900px 时转单栏；不大于 560px 时收紧外边距、面板内边距并纵向排列顶部区域。这是本批示例规则，不改全后台断点。
- 浮层显式传入 `popper-class="admin-ui-popover"`，沿用中文 Element Plus；窄屏限制日期面板宽度。日期单元格沿用组件库紧凑尺寸，44px 要求应用于主输入区，未扩展到每个日期格。二维日历应使用独立滚动区，不能裁切整页。
- 绿色表示可执行或明确成功，橙色表示关注与待办，红色用于明确失败；颜色始终配合文字。反馈可组合，保存成功与后续待办、确认成功与刷新失败不是互斥状态。
