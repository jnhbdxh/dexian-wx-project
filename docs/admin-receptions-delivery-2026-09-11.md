## 交付内容

- 后台 `/receptions`：服务日期、状态、美容师、完整接待号查询，每页 25 组；北京时间服务区间与当天相交，跨午夜在两日均可查，仅准备／休息跨日不计入。
- API：`GET /api/v1/admin/receptions`、`GET /api/v1/admin/receptions/:receptionId`。列表、总数和详情按同一读取事务中的数据库时间判断到期，无需等待清理任务。分页游标失效会提示并回到第一页。
- 详情分开呈现服务、准备、整理／清洁、必要休息、人员和房床；根据资源 ID 区分同名资源。时间经过不推断到店、完工或收款。
- 已验证手机号只显示脱敏值；无数据明确说明。权限沿用 `operations.overview.read`、`receptions.confirm` 和 `payments.review.read`。无资金读取权限不返回支付明细，内部请假原因不返回新查询接口。未登录、无权限、跨门店、记录不存在分别处理。
- 复用既有确认事务，操作结束刷新列表和详情；版本竞争提示核对最新状态。重复确认已有确认记录时沿用既有服务端成功结果，页面不会宣称是本员工刚完成的操作。
- 请求发出前将接待号、版本、幂等键及员工／门店写入会话存储。网络未知、忙碌或权限中断保留原请求；恢复后用原账号、原参数核实。存储失败不发送确认。
- 每 15 秒后台更新；保持详情节点，避免自动刷新丢失操作焦点。账号变化或读取权限失效清除受保护内容。窄屏选择记录后定位详情，并可返回列表。
- 无新增数据库迁移。依赖工作区现有 Schema 和 `0005—0008` 迁移成果；没有改写支付／短信／微信接入业务。
